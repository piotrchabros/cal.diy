# Tasks: Meeting Transcription Notetaker

**Input**: Design documents from `/specs/001-meeting-transcription/`

**Prerequisites**: plan.md (required), spec.md (required for user stories), research.md, data-model.md, quickstart.md, contracts/

**Tests**: Test tasks are included. The constitution (Principle III) requires at least 80% coverage on new code, and `research.md` Decision 13 defines the test strategy: Vitest unit tests next to the source as `*.test.ts` with repositories replaced by in-memory fakes that implement the repository interfaces, `*.integration-test.ts` for the dispatch compare-and-swap, cascade delete and passage upsert idempotency, route tests for the events route, and one Playwright file. Within each phase the test tasks come before the implementation tasks they cover and must fail first.

**Organization**: Tasks are grouped by user story so each story can be implemented and tested on its own. The plan groups the same work into PRs by layer; every task ends with the plan PR it belongs to, and the table in "Dependencies & Execution Order" maps each PR back to its tasks.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task of the same phase)
- **[Story]**: Which user story the task belongs to (US1..US6); tasks in Setup, Foundational, the bot phase and Polish carry no story label
- Every task names the exact file path(s) it creates or changes and ends with its plan PR, for example `(PR 5)`

## Path Conventions

- Paths are relative to the repository root of the Yarn/Turbo monorepo.
- Feature slice: `packages/features/notetaker/` (repositories behind interfaces, services, DI modules, Trigger.dev tasker).
- DTOs and the bot wire contract: `packages/lib/dto/` and `packages/lib/notetaker/botContract.ts`.
- tRPC: `packages/trpc/server/routers/viewer/notetaker/` and `packages/trpc/server/routers/publicViewer/`.
- Hooks and components that use tRPC: `apps/web/modules/notetaker/` only.
- Bot service: `apps/notetaker-bot/`.
- Rules that apply to every task: Prisma only inside repositories and always with `select`, never `include`; services throw `ErrorWithCode` and never `TRPCError`; no `as any`; `import type` for type imports; no barrel imports; `packages/features` never imports `@calcom/trpc` or `apps/web`; every UI or email string goes through `t()` with a key in `packages/i18n/locales/en/common.json`; no `*.generated.ts` file is edited by hand.
- Names not fixed by the design documents (repository method names, DI module file names, test file names, i18n keys other than `notetaker_display_name` and `notetaker_meeting_notice`) are derived from the house patterns in `agents/rules/` and the plan's wildcard entries (`di/<Class>.module.ts`, `<Service>.container.ts`, `interfaces/I*.ts`, `Notetaker*.tsx`). New i18n keys use the prefix `notetaker_`; status labels are `notetaker_status_` plus the lowercase enum value, outcome reasons `notetaker_reason_` plus the lowercase enum value, and ineligibility reasons `notetaker_unavailable_` plus the lowercase reason.
